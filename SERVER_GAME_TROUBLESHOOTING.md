# Игра на сервере не работает: быстрый план диагностики

Ниже — минимальный и практичный чеклист, который помогает найти проблему в 90% случаев.

## 1) Проверить, что процесс игры/бэкенда вообще запущен

```bash
ps aux | rg -i "node|python|java|game|server"
```

Если процесс не найден — сначала запустите приложение вручную и сразу смотрите ошибки в консоли.

## 2) Проверить, слушает ли нужный порт

```bash
ss -ltnp | rg ":3000|:8080|:80|:443"
```

Замените порт на ваш реальный (например, 3000/8080).

## 3) Проверить локально на сервере (без интернета)

```bash
curl -i http://127.0.0.1:3000/
```

Если локально не отвечает — проблема в приложении, а не в DNS/прокси.

## 4) Проверить firewall/security group

- Откройте порт приложения в UFW/iptables/security-group.
- Для Linux + UFW:

```bash
sudo ufw status
sudo ufw allow 3000/tcp
```

## 5) Проверить reverse proxy (Nginx/Caddy/Traefik)

Если используете Nginx:

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
sudo tail -n 200 /var/log/nginx/error.log
```

Типичная ошибка: прокси смотрит не на тот порт или upstream недоступен.

## 6) Проверить переменные окружения

Часто падение из-за отсутствия `.env` значений:

- `PORT`
- `NODE_ENV`
- `DATABASE_URL`
- ключи API/секреты
- URL фронтенда/бэкенда (CORS)

## 7) Проверить логи приложения

Если через systemd:

```bash
sudo systemctl status my-game --no-pager
sudo journalctl -u my-game -n 200 --no-pager
```

Если через PM2:

```bash
pm2 list
pm2 logs --lines 200
```

## 8) Проверить БД и миграции

- Доступна ли БД с сервера.
- Выполнены ли миграции.
- Совпадают ли версии схемы между локальной и сервером.

## 9) Частые причины именно у игр

- WebSocket не проксируется (`Upgrade`/`Connection` заголовки в Nginx).
- CORS блокирует запросы клиента.
- Неверный публичный URL для клиента (`wss://...` вместо `ws://...` под HTTPS).
- Серверное время/таймзона приводит к сбоям токенов и сессий.

## 10) Минимальный набор данных для точной помощи

Чтобы быстро найти причину, соберите и пришлите:

1. Точную ошибку из браузера (Console + Network).
2. Последние 100–200 строк логов приложения.
3. Как запускаете сервис (systemd/pm2/docker).
4. Конфиг прокси (например, `nginx server { ... }`).
5. Какой домен/порт и где именно «ломается» (загрузка, логин, матчмейкинг, websocket).

---

Если хотите, можно идти пошагово: сначала пришлите вывод пунктов 2, 3 и 7 — этого обычно достаточно для первого точного диагноза.
